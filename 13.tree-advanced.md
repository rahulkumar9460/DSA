# SEGMENT TREE

arr = [1, 3, 5, 7]

## BUILD

```
Segment Tree:
                16
              /    \
             4      12
           /  \    /  \
          1    3  5    7
```

16 = sum[0, 3]
4  = sum[0, 1]
12 = sum[2, 3]
1  = sum[0, 0]
3  = sum[1, 1]
5  = sum[2, 2]
6  = sum[3, 3]

> [!IMPORTANT]
>               Segment tree represented as tree:
>                     16, 4, 12, 1, 3, 5, 7
>               idx =  0, 1,  2, 3, 4, 5, 6
>
>               for idx, its left node will be at  = idx*2 + 1
>               for idx, its right node will be at = idx*2 + 2 

Why we represent tree as an array?
Because:

1. arrays are fast
2. no pointer tree needed
3. memory cache friendly
4. easier implementation

```cpp
void build(int idx, int low, int high, vector<int>&arr) {
    //build segment tree node at idx for given arr[low....high]

     // node has single element --> leaf node
    if(low == high) {
        seg[idx] = arr[low];
        return;
    }

    int mid = (low + high)/2;

    // build left segment tree
    build(idx*2 + 1, low, mid, arr);

    // build right segment tree
    build(idx*2 + 2, mid+1, high, arr);

    seg[idx] = seg[idx*2 + 1] + seg[idx*2 + 2];
}
// O(n)
```

## QUERY

```
                [0,3] = 16
               /             \
        [0,1] = 4          [2,3] = 12
         /      \           /       \
 [0,0]=1   [1,1]=3   [2,2]=5   [3,3]=7
```

query[1, 2] ==> give sum of range arr[1..2]

> [!IMPORTANT]
>
>                For a query ask: "Does this segment contribute to my answer?"
>
> A segment can contribute in three manners: 
>
> There are three cases
> - case 1: No overlap: Segment outside query
>
>               segment tree node = [0, 0] and query = [1, 2]
>               no common element, segment node doesn't contribute, so contribution = 0;
>
> - case 2: Complete overlap: Segment inside query
>
>               segment tree node = [2, 2] and query = [1, 2]
>               complete segment node contributes: so contribution = 5
>
> - case 3: Partial overlap:
>
>               segment tree node = [0, 3] and query = [1, 2]
>               segment node contains sum from 0 to 3 = 16, we cant not return it
>                   So we need to split it:
>                   1. node = [0, 1] and query = [1, 2]
>                   2. node = [2, 3] and query = [1, 2] 


Lets take one example:
```
query[1, 2] ==> get sum from index 1 to 2

- Start from root node of segment tree which is [0, 3]
    partial overlap: split it: [0, 1] and [2, 3]

    - seg[0, 1] and query[1, 2]
        partial overlap: split it: [0, 0] and [1, 1]
        
        - seg[0, 0] and query[1, 2]
            no overlap: contribution = 0
        
        - seg[1, 1] and query[1, 2]
            complete overlap: entire segment contributes = 3
        
    - seg[2, 3] and query[1, 2]
        partial overlap: split it: [2, 2] and [3, 3]

        - seg[2, 2] and query[1, 2]
            complete overlap: entire segment contributes = 5
        
        - seg[3, 3] and query[1, 2]
            no overlap: contribution = 0


Total contribution = 0 + 3 + 5 + 0 = 8
```

```cpp
int query(int idx, int low, int high, int ql, int qr) {
    // query = [ql, qr]
    // idx = segment tree index
    // segment node at idx covers = [low, high]

    // no overlap, segment outside query
    if(high < ql  || low > qr )
        return 0;

    // complete overlap, segment inside query
    if(low >= ql && high <= qr)
        return seg[idx];

    int mid = (low + high)/2;
    
    int left  = query(idx*2+1, low, mid, ql ,qr);
    int right = query(idx*2+2, mid+1, high, ql, qr);

    // partial overlap
    return left + right;
}

// O(log(n))
```

## UPDATE

```
                [0,3] = 16
               /             \
        [0,1] = 4          [2,3] = 12
         /      \           /       \
 [0,0]=1   [1,1]=3   [2,2]=5   [3,3]=7
```

> Update arr[2] = 10

> Segments that contain 2 will be affected:

- [0, 3], [2, 3] and [2, 2]         are affected
- [0, 1], [0, 0], [1, 1], [3, 3]    are not affected

> [!IMPORTANT]
>
>               "Does this segment contain index i?"
>
> Recursion idea
>
> - suppose update index 2
> - we start from [0, 3]
> - mid is 1 so check where is 2?, left = [0, 1] or right = [2, 3]
> - 2 is in right, so only update right
>
>       - Now node is [2, 3], mid = 2
>       - left = [2, 2] and right = [3, 3]
>       - 2 is in left, so update only left
>
>           - Now node is [2, 2], leaf node reached
>           - update the value seg[idx] = 10
>
>                   While Recursion retruns: Recalculate the parent's value
>                   For example: seg[2, 3] = 12 but now it is = 10+7   = 17
>                                                   now root [0, 3] is = 4+17 = 21


```cpp
void update(int idx, int low, int high, int i, int value) {
    // leaf node
    if(low == high) {
        seg[idx] = value;
        return;
    }

    int mid = (low+high)/2;

    // if i is in left part
    if(i <= mid) update(idx*2+1, low, mid, i, value);

    // else i is in right part
    else update(idx*2+2, mid+1, high, i, value);

    // recalculate parent
    seg[idx] = seg[idx*2+1] + seg[idx*2+2];
}

// O(log(n))
```

## 1. Range Sum Query - Mutable
[Leetcode link](https://leetcode.com/problems/range-sum-query-mutable/description/)

Given an integer array nums, handle multiple queries of the following types:

1. Update the value of an element in nums.
2. Calculate the sum of the elements of nums between indices left and right inclusive where left <= right.

```cpp
class SegmentTree {
    vector<int> seg;
public:
    SegmentTree(int n) {
        seg.resize(4*n, 0);
    }

    void build(int idx, int low, int high, vector<int>&arr) {
        if(low == high) {
            seg[idx] = arr[low];
            return;
        }

        int mid = (low+high)/2;

        build(idx*2+1, low, mid, arr);
        build(idx*2+2, mid+1, high, arr);

        seg[idx] = seg[idx*2+1] + seg[idx*2+2];
    }

    int query(int idx, int low, int high, int ql, int qr) {
        // no overlap
        if(high < ql || low > qr) return 0;

        // complete ovelap; segment inside query
        if(low >= ql && high <= qr) return seg[idx];

        int mid = (low+high)/2;
        int left = query(idx*2+1, low, mid, ql, qr);
        int right = query(idx*2+2, mid+1, high, ql, qr);

        return left + right;
    }

    void update(int idx, int low, int high, int i, int value) {
        if(low == high) {
            seg[idx] = value;
            return;
        }

        int mid = (low+high)/2;
        if(i <= mid) update(idx*2+1, low, mid, i, value);
        else update(idx*2+2, mid+1, high, i, value);

        seg[idx] = seg[idx*2+1] + seg[idx*2+2];
    }
};

class NumArray {
    SegmentTree sgt;
    int n;
public:
    NumArray(vector<int>& nums) : sgt(nums.size()) {
        this->n = nums.size();
        sgt.build(0, 0, n-1, nums);
    }
    
    void update(int index, int val) {
        sgt.update(0, 0, n-1, index, val);
    }
    
    int sumRange(int left, int right) {
        return sgt.query(0, 0, n-1, left, right);
    }
};
```

# Lazy Propagation

> current update
>
> we only update one index arr[4] = 10 

> [!IMPORTANT]
> Suppose we need to: Add +3 to every element from [2,7]
> 
>               for(i=2; i<=7; i++)
>                   update(...)
>
>               If we do update for 2 <= i <= 7 ==> it takes (high-low+1) * log(n) time complexity
>                   which is O(nlog(n)

```
Lazy Propagation Idea

Instead of updating immediately
    - postpone the updates for later
    - apply only when needed
```

> [!NOTE]
> Main idea befind lazy propogation is:
>           
>           Instead of updating children immediately
>           Update this segment when needed
>
>           To minimise the work in case of range-updates (ex. add +3 for range [3, 9])

## Most important intuition
```
arr = [1,3,5,7] 

                [0,3] = 16
              /               \
        [0,1]=4            [2,3]=12

update: add +10 for range[0, 3]

Do we REALLY need to go to all leaf nodes? ----- NO
```

> [!IMPORTANT]
> Instead of going deeper:
> - just update root directly.
>
>                   old = 16
>                   new = 16 + 4*10 = 56
>                       why 4*10, because segment length is 4 = (3-0+1)
>
>                   But now children has outdated value
>                   So we need to mark this node [0, 3] has pending children
>                       like: lazy[idx]
>
>                   lazy array stores pending updates
>
>                    suppose: update [0,3] by +10
>                    We do: seg[root] = 56
>                    And mark:
>                           lazy[left child]  += 10
>                           lazy[right child] += 10
>                   meaning: children still need +10 later
>
> - WHAT DOES LAZY ARRAY MEAN?
>                   suppose: lazy[5] = 7
>                   it means:
>                       "Before using node 5,
>                       apply pending +7 update."
>
> - WHEN DO WE PUSH LAZY?
>                   Whenever we visit a node
>                       1. for query
>                       2. for update
>                               First: resolve pending lazy update: push(idx, low, high)
>                               push() --> applies lazy changes to node at idx and its children node and remove lazy at idx


```cpp
void push(int idx, int low, int high) {
    // no pending update
    if(lazy[idx] == 0)
        return;

    // apply pending update
    seg[idx] += (high - low + 1) * lazy[idx];

    // if it has children
    if(low != high) {
        lazy[2*idx+1] += lazy[idx];
        lazy[2*idx+2] += lazy[idx];
    }

    // clear lazy
    lazy[idx] = 0;
}

void rangeUpdate(int idx, int low, int high, int rl, int rr, int val) {
    // update for range [rl, rr] with val
    // resolve pending updates
    push(idx, low, high);

    // no overlap
    if(high < rl || low > rr)
        return;

    // complete overlap
    if(low >= rl && high <= rr) {
        seg[idx] += (high-low+1) * val; // update root node

        if(low != high) {
            // mark children node with pending update
            lazy[2*idx+1] += val;
            lazy[2*idx+2] += val;
        }

        return;
    }

    // partial overlap
    int mid = (low + high) / 2;
    rangeUpdate(2*idx+1, low, mid, rl, rr, val);
    rangeUpdate(2*idx+2,  mid+1, high, rl, rr, val);

    seg[idx] = seg[2*idx+1] + seg[2*idx+2];
}

int query(int idx, int low, int high, int ql, int qr) {
    push(idx, low, high);

    // no overlap
    if(high < ql || low > qr)
        return 0;

    // complete overlap
    if(low >= ql && high <= qr) return seg[idx];

    int mid = (low + high) / 2;
    int left = query(2*idx+1, low, mid, ql, qr);
    int right = query(2*idx+2, mid+1, high, l, r);

    return left + right;
}
```

# Fenwik or BIT tree

> [!NOTE]
> - idx += idx & -idx
> - idx -= idx & -idx

### What is idx & -idx ?
> It extracts the rightmost set bit also called as "Low bit"
```
| idx | binary | idx & -idx |
| --- | ------ | ---------- |
| 12  | 1100   | 0100 = 4   |
| 10  | 1010   | 0010 = 2   |
| 7   | 0111   | 0001 = 1   |
| 8   | 1000   | 1000 = 8   |

```

### What does LOWBIT represent?
> It tells the size of the segment this BIT node is responsible for.
```
| idx | binary | lowbit | range size |
| --- | ------ | ------ | ---------- |
| 6   | 0110   | 2      | size 2     |
| 8   | 1000   | 8      | size 8     |
| 12  | 1100   | 4      | size 4     |

```

> [!IMPORTANT]
> bit[idx] stores the combined result of lowbit(idx) indices ending at idx.
>
> Example:
>
>            bit[6]: 6=0110, lowbit=2 → stores [5,6]
>            bit[8]: 8=1000, lowbit=8 → stores [1...8]
>            bit[12]: 12=1100, lowbit=4 → stores [9...12]
>
>To compute prefixSum(13):
>
>            13=1101, lowbit=1
>            take bit[13] → [13]
>            remaining needed: [1...12]
>
>            move: 13 - 1 = 12
>            12=1100, lowbit=4
>            take bit[12] → [9...12]
>            remaining needed: [1...8]
>
>            move: 12 - 4 = 8
>            8=1000, lowbit=8
>            take bit[8] → [1...8]
>            remaining needed: nothing
>
>            move: 8 - 8 = 0
>
> Final decomposition:
>
>            [1...13] = [13] + [9...12] + [1...8]

```cpp
class Fenwick {
    vector<int> bit;
    int n;

public:
    Fenwick(int n) {
        this->n = n;
        bit.resize(n + 1, 0);
    }

    void add(int idx, int val) {
        idx++; // 1-indexed

        while(idx <= n) {
            bit[idx] += val;
            idx += idx & -idx;
        }
    }

    int sum(int idx) {
        idx++;
        int ans = 0;

        while(idx > 0) {
            ans += bit[idx];
            idx -= idx & -idx;
        }
        return ans;
    }

    int rangeSum(int l, int r) {
        return sum(r) - (l ? sum(l - 1) : 0);
    }
};
```

## 2.  Maximum Sum Obtained of Any Permutation
[Leetcode link](https://leetcode.com/problems/maximum-sum-obtained-of-any-permutation/description/)

- Input: nums = [1,2,3,4,5], requests = [[1,3],[0,1]]
- Output: 19

Explanation: 
    One permutation of nums is [2,1,3,4,5] with the following result: 
    requests[0] -> nums[1] + nums[2] + nums[3] = 1 + 3 + 4 = 8
    requests[1] -> nums[0] + nums[1] = 2 + 1 = 3
    Total sum: 8 + 3 = 11.

    A permutation with a higher total sum is [3,5,4,2,1] with the following result:
    requests[0] -> nums[1] + nums[2] + nums[3] = 5 + 4 + 2 = 11
    requests[1] -> nums[0] + nums[1] = 3 + 5  = 8
    Total sum: 11 + 8 = 19, which is the best that you can do.

### Intuition
> [!IMPORTANT]
> Assign max value to most frequent index == greedy
>
> nums = [1,2,3,4,5], requests = [[1,3],[0,1]]
>            then sum[i] = nums[i]*freq[i]
>
>            freq = [1, 2, 1, 1, 0]
>            nums = [1, 2, 3, 4, 5]
>
>            sort both nums and feq:
>            freq = [0, 1, 1, 1, 2]
>            nums = [1, 2, 3, 4, 5]
>            sum  = [0, 2, 3, 4, 10] = 19
>
> How do we find frequencies?
>  
>               For each request r we update frequencies for all indicies from r[0] to r[1] 
>               we will get TLE: since o(n^2)
>
>               Use sweep line:
>                   update freq[r[0]] = 1 and freq[r[1]+1] = -1
>                   Now to get freq of index i just take prefix sum till index i = sum of freq[0] to freq[i]
>
>               To get prefix sum use Fenwik tree

```cpp
int maxSumRangeQuery(vector<int>& nums, vector<vector<int>>& requests) {
    int n = nums.size();
    Fenwik fenwik(n);

    for(auto &r: requests) {
        fenwik.add(r[0], 1);
        if(r[1]+1 < n) fenwik.add(r[1]+1, -1);
    }

    vector<int> freq(n, 0);
    for(int i=0; i<n; i++) {
        freq[i] = fenwik.sum(i);
    }

    sort(freq.begin(), freq.end());
    sort(nums.begin(), nums.end());

    int mod = 1e9+7;
    long long ans = 0;

    for(int i=0; i<n; i++) {
        ans += 1LL*nums[i]*freq[i];
        ans = ans%mod;
    }

    return (int)ans;
}
```

## 3. Count of Smaller Numbers After Self
[Leetcode link](https://leetcode.com/problems/count-of-smaller-numbers-after-self/description/)

> Given an integer array nums, return an integer array counts where counts[i] is the number of smaller elements to the right of nums[i].

- Input: nums = [5,2,6,1]
- Output: [2,1,1,0]

### Intuition
> [!IMPORTANT]
> We need to count the number of smaller elements on right side
>
> In other words we need to sum all frequencies of elements smaller than nums[i] on the right side
>
> we can store frequencies Using Fenwik Tree
>
> Then we can take prefix sum over frequencies for all elements less than nums[i]
>
>               nums = [5,2,6,1,100,4,1000,56]
>               freq = [[5, 1], [2, 1], [6, 1], [1, 1], [100, 1], [4, 1], [1000, 1], [56, 1]]
>               If we use array to store freq then we need size of 1000 --> not feasible
>
>               Use coordinate compression:
>               sortedNums = [1, 2, 4, 5, 6, 56, 100, 1000]
>                   map    = [0, 1, 2, 3, 4, 5,  6,   7]
>
>               Now every element is mapped to a smaller element ans we work with this only
>               now nums become = [3, 1, 4, 0, 6, 2, 7, 5] --> coordinates are compressed now
>
>               For easier impementation reverse nums = [5, 7, 2, 6, 0, 4, 1, 3]
>               
> Simulation:
>               
>               At i = 0: nums[0] = 5, freq = [0, 0, 0, 0, 0, 1, 0, 0], elements less than 5 = 0 = prefix sum till index 4
>               At i = 1: nums[1] = 7, freq = [0, 0, 0, 0, 0, 1, 0, 1], elements less than 7 = 1 = prefix sum till index 6
>               At i = 2: nums[2] = 2, freq = [0, 0, 1, 0, 0, 1, 0, 1], elements less than 2 = 0 = prefix sum till index 1
>               .
>               .
>               At i = 7: nums[7] = 3, freq = [1, 1, 1, 1, 1, 1, 1, 1], elements less than 3 = 2 = prefix sum till index 2

```cpp
unordered_map<int, int> getMapped(vector<int> &nums) {
    vector<int> sortedNums(nums.begin(), nums.end());
    sort(sortedNums.begin(), sortedNums.end());

    // coordinate compression
    unordered_map<int, int> mp;
    int i = 0;
    for(int num : sortedNums) {
        if(mp.count(num)) continue;
        else mp[num] = i++;
    }
    return mp;
}

vector<int> countSmaller(vector<int>& nums) {
    reverse(nums.begin(), nums.end());
    unordered_map<int, int> mp = getMapped(nums);

    int n = nums.size();
    Fenwik fenwik(n);

    vector<int> ans(n, 0);
    for(int i=0; i<n; i++) {
        int mappedNum = mp[nums[i]];

        ans[i] = fenwik.sum(mappedNum-1);

        fenwik.add(mappedNum, 1);
    }   

    reverse(ans.begin(), ans.end());
    return ans;
}
```

## 4. Count of Range Sum
[Leetcode link](https://leetcode.com/problems/count-of-range-sum/description/)

Given an integer array nums and two integers lower and upper, return the number of range sums that lie in [lower, upper] inclusive.

Range sum S(i, j) is defined as the sum of the elements in nums between indices i and j inclusive, where i <= j.

 
- Input: nums = [-2,5,-1], lower = -2, upper = 2
- Output: 3
- Explanation: The three ranges are: [0,0], [2,2], and [0,2] and their respective sums are: -2, -1, 2.

### Intuition
> [!IMPORTANT]
>
>            lower <= subarrySum <= upper
>            lower <= currPrefix - prevPrefix <= upper
>            lower - currPrefix <= -prevPrefix <= upper-currPrefix
>
>            currPrefix-upper <= prevPrefix <= currPrefix-lower
>
>                   so for currPrefix the prevPrefix must be in range [currPrefix-upper, currPrefix-lower]
>
>            if upper = u, lower = l, currPrefix = c
>            find number of sums between [c-u, c-l] ==> [a, b]
>
>            
>                   find number of elements between [a, b]
>                   use BIT ==> mark frequency of elements
>

```cpp
unordered_map<long long, int> getMapped(vector<long long> &nums) {
    vector<long long> sortedNums(nums.begin(), nums.end());
    sort(sortedNums.begin(), sortedNums.end());

    // coordinate compression
    unordered_map<long long, int> mp;
    int i = 0;
    for(long long num : sortedNums) {
        if(mp.count(num)) continue;
        else mp[num] = i++;
    }
    return mp;
}

int countRangeSum(vector<int>& nums, int lower, int upper) {
    int n = nums.size();

    vector<long long> prefixSum;
    prefixSum.push_back(0);
    long long sum = 0;
    for(int i=0; i<n; i++) {
        sum += nums[i];
        prefixSum.push_back(sum);
    }

    vector<long long>allSum = prefixSum;
    for(long long pSum : prefixSum) {
        allSum.push_back(pSum-lower);
        allSum.push_back(pSum-upper);
    }

    unordered_map<long long, int> mp = getMapped(allSum); // coordinate compression

    Fenwik fenwik(allSum.size());
    int ans = 0;
    for(long long sum : prefixSum) {

        int l = mp[sum - upper];
        int h = mp[sum - lower];

        ans += fenwik.rangeSum(l, h);

        fenwik.add(mp[sum], 1);
    }

    return ans;
}
```

## 5. Reverse Pairs
[Leetcode link](https://leetcode.com/problems/reverse-pairs/description/)

Given an integer array nums, return the number of reverse pairs in the array.

A reverse pair is a pair (i, j) where:

0 <= i < j < nums.length and
nums[i] > 2 * nums[j].
 

- Input: nums = [1,3,2,3,1]
- Output: 2
- Explanation: The reverse pairs are:
- (1, 4) --> nums[1] = 3, nums[4] = 1, 3 > 2 * 1
- (3, 4) --> nums[3] = 3, nums[4] = 1, 3 > 2 * 1

### Intuition
> [!IMPORTANT]
>
> nums[i] > 2*nums[j] : j > i
>
>                   for element curr we need to find all elements greater than 2*curr
>
>                   Count problem ==> frequency and prefix sum => BIT
>                   
>                   for nums[i], number of elements greater than 2*nums[i] = i - fenwik.sum(2*nums[i])
>                   We count all elements <= 2*nums[i] and substract that from total

```cpp
int reversePairs(vector<int>& nums) {
    int n = nums.size();

    vector<long long> all(nums.begin(), nums.end());
    for(int num: nums) all.push_back(1LL*2*num);

    unordered_map<long long, int> mp = getMapped(all);

    Fenwik fenwik(mp.size());
    int ans = 0;

    for(int i=0; i<n; i++) {
        int count = fenwik.sum(mp[1LL*2*nums[i]]); 
        ans += i - count;

        fenwik.add(mp[nums[i]], 1);
    }

    return ans;
}
```

## 6. Create Sorted Array through Instructions
[Leetcode link](https://leetcode.com/problems/create-sorted-array-through-instructions/description/)

Input: instructions = [1,5,6,2]

Output: 1

Explanation: Begin with nums = [].
- Insert 1 with cost min(0, 0) = 0, now nums = [1].
- Insert 5 with cost min(1, 0) = 0, now nums = [1,5].
- Insert 6 with cost min(2, 0) = 0, now nums = [1,5,6].
- Insert 2 with cost min(1, 2) = 1, now nums = [1,2,5,6].
- The total cost is 0 + 0 + 0 + 1 = 1.

### Intuition
> [!IMPORTANT]
> we need:
> 1. smaller = number of elements smaller than nums[i] = fenwik.sum(nums[i]-1)
> 2. greater = number of elements greater than nums[i] = i - fenwik.sum(nums[i])
>
> use coordinate compression

```cpp
unordered_map<int, int> getMapped(vector<int> &nums) {
    vector<int> sorted(nums.begin(), nums.end());
    sort(sorted.begin(), sorted.end());

    unordered_map<int, int> mp;
    int i = 0;
    for(int n: sorted) {
        if(!mp.count(n)) mp[n] = i++;
    }
    return mp;
}

int createSortedArray(vector<int>& instructions) {
    int n = instructions.size();
    unordered_map<int, int> mp = getMapped(instructions);

    long long ans = 0;
    int mod = 1e9+7;

    Fenwik fenwik(mp.size());

    for(int i=0; i<n; i++) {
        int idx = mp[instructions[i]];

        int smaller = fenwik.sum(idx-1);
        int greater = i - fenwik.sum(idx);

        ans += 1LL*min(smaller, greater);
        ans %= mod;

        fenwik.add(idx, 1);
    }

    return ans;
}
```

## 7. Number of Pairs Satisfying Inequality
[Leetcode link](https://leetcode.com/problems/number-of-pairs-satisfying-inequality/description/)

You are given two 0-indexed integer arrays nums1 and nums2, each of size n, and an integer diff. Find the number of pairs (i, j) such that:

> 0 <= i < j <= n - 1 and
> nums1[i] - nums1[j] <= nums2[i] - nums2[j] + diff.
> Return the number of pairs that satisfy the conditions.

### intuition
> [!IMPORTANT]
> Rephrase:
>
>               nums1[i] - nums1[j] <= nums2[i] - nums2[j] + diff
>               nums1[i] - nums2[i] <= nums1[j] - nums2[j] + diff
>               
>               make a new arr = num1 - nums2
>               Now: arr[i] <= arr[j] + diff and j > i
>               
>               arr[j] + diff  >= arr[i] (j > i)
>
>               for current element find all previous element which are <= (curr + diff)
>
>               use frequency + prefix sum to get number <= (curr+diff)
>
>               Use BIT/Fenwik

```cpp
long long numberOfPairs(vector<int>& nums1, vector<int>& nums2, int diff) {
    int n = nums1.size();
    for(int i=0; i<n; i++) nums1[i] -= nums2[i];

    vector<int> all(nums1.begin(), nums1.end());
    for(int num: nums1) all.push_back(num+diff); //imp

    unordered_map<int, int> mp = getMapped(all);

    long long ans = 0;
    Fenwik fenwik(mp.size());

    for(int num : nums1) {
        ans += 1LL*fenwik.sum(mp[num+diff]);

        fenwik.add(mp[num], 1);
    }

    return ans;
}
```
